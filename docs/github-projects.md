# GitHub 프로젝트

Windows 앱의 `＋ GitHub에서 추가`에서 계정을 연결한 뒤 저장소를 고릅니다. 공식 GitHub CLI가 이미 로그인되어 있으면 해당 계정을 사용합니다. 아니면 앱에 표시되는 일회용 코드를 GitHub 인증 화면에 입력합니다. Tidewatch가 대신 로그인하거나 인증 승인을 누르지는 않습니다.

- `기존 폴더 연결`: 최초 한 번 폴더를 고릅니다. 해당 폴더의 Git origin이 선택한 저장소인지 검사합니다. HTTPS·SSH GitHub origin을 지원합니다.
- `이 컴퓨터에 받기`: 선택한 저장소를 `~/.tidewatch/workspaces/<owner>/<repo>`로 받습니다. 기존 경로를 덮어쓰거나 실패한 폴더를 자동 삭제하지 않습니다. 서브모듈은 자동으로 받지 않습니다.
- 프로젝트 등록 후에는 Claude·Codex를 선택하고 `새 작업` 또는 `이어하기`를 누릅니다. 폴더 선택 없이 해당 위치에서 터미널이 열립니다. 이어하기는 CLI의 대화 선택 목록을 엽니다. 원본 대화 ID와 카드 자동 연결, 기존 실행 창 포커스 이동은 아직 지원하지 않습니다. 실행 중인 대화를 다른 터미널에서 중복 재개하지 마세요.
- 프로젝트 `등록 해제`는 목록에서만 지웁니다. 실제 작업 폴더는 유지합니다.

## 인증과 권한

GitHub CLI 2.103.3을 공식 배포 파일의 SHA-256을 검증해 번들로 포함합니다. 사용자에게 별도 gh 설치를 요구하지 않습니다. Git, Claude Code·Codex, 상태 갱신용 Node.js는 별도 설치가 필요합니다.

인증 화면에는 Tidewatch 전용 OAuth 앱이 아닌 **GitHub CLI**가 표시됩니다. CLI의 기본 권한은 `repo`, `read:org`, `gist`이며 단순 읽기 전용 권한보다 넓습니다. Tidewatch가 구현한 동작은 로그인 계정 확인, 접근 가능한 저장소 목록 조회, 사용자가 선택한 저장소 받기입니다. 커밋·푸시·PR 생성은 자동으로 하지 않습니다. [공식 GitHub CLI 인증 안내](https://cli.github.com/manual/gh_auth_login)

자격 증명은 GitHub CLI가 관리합니다. 시스템 자격 증명 저장소를 사용할 수 없으면 CLI가 평문 파일 저장으로 대체할 수 있습니다. Tidewatch 프로젝트 JSON이나 화면에 인증 토큰을 복사하지 않습니다. 앱의 `연결 해제`는 Tidewatch의 계정 조회를 멈추며 등록 프로젝트와 기존 GitHub CLI 로그인은 유지합니다. 다른 CLI 사용에 영향을 주는 전체 로그아웃은 실행하지 않습니다. OAuth 승인은 GitHub 설정의 Applications에서 직접 취소할 수 있습니다.

GitHub.com을 지원하며 Enterprise 호스트는 지원하지 않습니다. 비공개·조직 저장소는 로그인 계정의 권한과 조직 승인이 필요합니다. 목록은 최근 push 순서로 100개씩 불러오며 검색은 불러온 목록을 대상으로 합니다. 프로젝트는 계정 연결을 해제해도 로컬에서 실행할 수 있습니다.

프로젝트 경로·저장소 이름·최근 실행 시간은 `~/.tidewatch/projects.json`, Tidewatch 연결 사용 여부는 `github-connection.json`에 저장됩니다. 이 파일들에 대화 내용이나 토큰은 저장하지 않습니다.

## 검증 범위

자동 검사에서는 인증 코드 수신·성공·취소 상태, 비공개 저장소 표시, 저장소 이름 검증, origin 불일치 차단, 기존 폴더 연결, clone 인자, 저장 프로젝트 재개, 연결·등록 해제 시 폴더 보존을 확인합니다. 실제 계정의 브라우저 인증 승인은 사용자가 완료해야 합니다.
