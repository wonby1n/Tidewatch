# 완료·응답 요청 알림과 원래 앱 열기

## 여러 터미널을 함께 볼 때

각 Claude Code·Codex 세션에서 Tidewatch 스킬을 켜면 작업 상태를 한 화면에 모을 수 있습니다. 터미널의 모든 로그나 임의의 명령을 자동으로 감지하는 기능은 아닙니다. 세션이 상태를 기록해야 카드와 알림이 갱신됩니다.

- **작업 중:** 현재 작업과 진행 단계 확인.
- **너 차례:** 답장 모양의 응답 배지와 사용자가 해야 할 일 표시.
- **막힘:** 오류 요약과 막힌 단계 표시.
- **완료:** 결과 한 줄을 담은 OS 알림과 앱 안의 **방금 완료** 배너 표시.

같은 상태를 반복 갱신해도 알림을 다시 보내지 않습니다. 앱 시작 때 이미 끝나 있던 카드도 전부 다시 알리지 않습니다. 앱을 실행 중이면 약 1초 간격으로 상태 변화를 확인합니다. 아주 짧게 바뀌었다 되돌아온 상태는 감지하지 못할 수 있습니다.

## 알림 설정

**설정 → 알림**에서 켜고 끕니다. 앱 안의 최근 소식 배너는 OS 알림 설정과 별개로 상태 변화를 보여줍니다. Windows의 알림 허용·방해 금지·전체 화면 설정에 따라 배너 팝업이 표시되지 않고 알림 센터에만 남을 수 있습니다. 시스템의 보안·알림 설정을 임의로 바꾸지 않습니다.

앱이 열려 있으면 Tidewatch 앱에서 알림을 보내고, 기존 스크립트 알림과 중복되지 않게 합니다. 앱을 닫았더라도 에이전트가 계속 상태를 기록하고 build를 실행한다면 기존 OS 알림을 사용할 수 있습니다.

## 카드와 알림을 눌렀을 때

- **Claude 앱 작업:** 카드의 **Claude 열기** 또는 알림을 누르면 Claude 앱을 엽니다. 대화 링크가 없으면 정확한 세션을 자동 선택하지 않습니다.
- **대화 링크 연결:** 카드의 버튼에 해당 작업의 `https://claude.ai/chat/...` 또는 `https://claude.ai/code/...` 링크를 넣으면 카드별로 기억합니다. Claude 앱 버전, 계정과 링크 종류에 따라 세션 목록이나 기존 화면으로 열릴 수 있습니다. 특히 Code 세션으로 바로 이동하는 동작은 환경에 따라 추가 확인이 필요합니다.
- **터미널 작업:** 카드의 `origin`이 `terminal`이면 다른 앱에서 세션을 재개하지 않고 Tidewatch의 작업 카드로 돌아옵니다. 정확한 원본 터미널 창·탭을 앞으로 선택하는 기능은 아직 없습니다.
- **Codex:** 현재 원본 앱 이동 대신 Tidewatch 카드로 돌아옵니다.

링크는 로컬 `~/.tidewatch/session-links.json`에 저장합니다. 기존 Claude 대화 링크만 허용하며, 파일 열기·쉘 명령·자동 프롬프트 전송 매개변수를 포함한 주소는 실행하지 않습니다. 사용자를 대신해 답변이나 승인을 보내지 않습니다.

Windows 설치 파일은 알림 클릭용 `tidewatch://session/<card-id>` 주소를 등록합니다. 카드 ID는 원래 Claude 대화 ID가 아니므로 두 값을 혼동하지 마세요.

## 펫이 로딩 상태로 남으면

이 버전은 펫 창의 초기화 완료 신호를 확인하고, 요청이 실패하거나 오래 걸리면 버튼을 다시 사용할 수 있게 합니다. 문제가 계속되면 `~/.tidewatch/pet-error.log`에 시작 오류가 기록됩니다. 펫 실행 파일이 없는 경우도 성공으로 표시하지 않습니다.
