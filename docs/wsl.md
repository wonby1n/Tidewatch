# WSL Claude 연결

Windows 앱을 설치해도 Ubuntu 등 WSL의 홈에는 자동으로 스킬이나 Claude 훅이 설치되지 않습니다. 앱의 `설정 → WSL Claude 연결`을 누르면 실행 중인 배포판을 선택해 Windows 보드에 연결합니다. WSL과 Node.js는 별도 설치가 필요합니다. 중지된 배포판을 자동으로 켜지 않습니다.

설정 전의 `~/.claude/settings.json`을 시간 이름이 붙은 `.bak`으로 백업하고, 기존 설정·다른 훅을 유지하면서 Tidewatch 명령 훅을 추가합니다. 훅 스크립트와 연결 경로는 WSL의 `~/.tidewatch-wsl`에 저장합니다. 훅은 Windows 앱이 읽는 세션 폴더로 직접 기록합니다. WSL에 `~/.tidewatch`가 없으면 Windows 보드 폴더를 가리키는 링크를 만듭니다. 기존 폴더가 있으면 보존합니다.

이미 실행 중인 Claude는 `/hooks`에서 새 훅 설정을 확인하거나, 다음에 대화를 재개할 때 적용하세요. 앱이 대화를 종료하거나 대신 입력·승인하지 않습니다. `disableAllHooks`나 관리 정책으로 훅이 차단된 환경에서는 해당 정책을 임의로 바꾸지 않습니다.

시작, 요청 처리, 도구 실행, 승인 대기, 도구 오류, 응답 종료, 세션 종료를 표시합니다. **응답 종료는 작업 전체 완료를 뜻하지 않으므로** `너 차례`로 표시합니다. 백그라운드 작업·예약 작업이 남은 응답은 진행 상태를 유지합니다. 세부 로드맵이나 실제 진행률은 자동 추측하지 않습니다.

연결 시 WSL의 프로세스와 `~/.claude/sessions` 메타데이터를 비교해 현재 실행 중인 세션을 추가할 수 있습니다. 이 카드는 실제 상태 이벤트가 오기 전까지 `현재 단계는 다음 이벤트부터 표시`라고 알립니다. 종료된 과거 PID 파일은 가져오지 않습니다.

대화 본문, 사용자 요청, 명령 문자열, Claude 응답 내용은 기록하지 않습니다. 프로젝트 폴더, 원본 세션 ID, 배포판 이름, 이벤트 종류만 사용합니다. Windows 앱이 켜져 있으면 해당 상태 변화에 대해 Windows 알림을 보냅니다. 앱을 닫은 상태의 WSL Windows 알림은 지원하지 않습니다.

자동 생성 카드는 WSL 배포판과 실제 Claude 세션 ID를 기준으로 유지됩니다. 직접 Tidewatch 스킬을 실행해 만든 상세 계획 카드와는 별도입니다. 원본 터미널 탭으로 바로 이동하는 기능은 아직 지원하지 않습니다.
